# @atom63/figma

## 0.1.0-beta.1

### Minor Changes

- [#139](https://github.com/atom63/atom63-design-system/pull/139) [`34def03`](https://github.com/atom63/atom63-design-system/commit/34def03e468c6c9a618315d12205ac30ea1189a6) Thanks [@atom63](https://github.com/atom63)! - Generates the Button component set, bound to the token variables. `atom63-figma components` writes use_figma scripts from the generated component model, each under the 50,000-character limit, plus read-only check scripts. A token at an opacity (`color-mix(…)`) binds through a derived variable in a `Component` collection, whose Dev Mode code syntax is the CSS expression, because Figma gives a bound paint the variable's alpha; a bound paint verifies only when Figma's stored color matches what the variable resolves to, so a rerun repairs a stale one. The focus ring is a `Focus ring` layer drawn like the CSS `outline` (an outside stroke bound to the ring variables, shown only in `State=focusVisible`), so transparent variants show it too; a run removes the drop-shadow ring an earlier build wrote and keeps any other effect. A component result names what still differs: the first differing check of up to 12 variants, with short actual and expected values.

- [#141](https://github.com/atom63/atom63-design-system/pull/141) [`45f473a`](https://github.com/atom63/atom63-design-system/commit/45f473a02423faffddc85cdf458080baa84eb6a3) Thanks [@atom63](https://github.com/atom63)! - The Button component model carries a documentation block (summary, usage, related components, per-variant, size and state guidance, docs path) read from the agent index; the last component script part carries it.

- [#142](https://github.com/atom63/atom63-design-system/pull/142) [`77c54c3`](https://github.com/atom63/atom63-design-system/commit/77c54c310bf64c1a43423496d364e80aa03dc0a5) Thanks [@atom63](https://github.com/atom63)! - Add `buildDesignSystem`, `checkDesignSystem` and `readDesignSystemTable`: build the whole Atom63 design system in process (the token set with its text and effect styles, then every component and its spec card) with progress and one outcome whose status is pass, pending (only property references Figma is still reconciling) or fail, or `blocked` (nothing written, with a reason) when the file already holds a token set that is not provably Atom63's; check it read-only; and read what a file holds (the Atom63 table, any other token set by collection, whether a build would be refused, each component's set and card). `ComponentCounts` is now exported from the package root.

- [#144](https://github.com/atom63/atom63-design-system/pull/144) [`34e1811`](https://github.com/atom63/atom63-design-system/commit/34e1811fd418cbd0a43d7a23f2bcfda084fefe1d) Thanks [@atom63](https://github.com/atom63)! - Each component `Difference` now carries `nodeId`: the id of the node its check reads (the variant, one of its layers, or the spec card part), or, for a missing layer or part, the node it belongs in. A UI can select and zoom to it with `figma.getNodeByIdAsync`.

- [#125](https://github.com/atom63/atom63-design-system/pull/125) [`5047bc7`](https://github.com/atom63/atom63-design-system/commit/5047bc7b069223eb1949cbe4ce323bd7275a85cc) Thanks [@atom63](https://github.com/atom63)! - New package: the Figma token sync engine and token CSS reader, moved from the Cipher plugin.

- [#133](https://github.com/atom63/atom63-design-system/pull/133) [`5717365`](https://github.com/atom63/atom63-design-system/commit/571736513324762bd80b9764825f8dd2fc1b66bd) Thanks [@atom63](https://github.com/atom63)! - Add what the Figma plugin's Create and Import use: `brandRamp` generates a brand ramp in OKLCH, `buildTemplateFiles` writes the site template's token CSS from a few choices, `syncModel` and `checkModel` sync a token set in process with the same results as the scripts, and `readTokenTable` reads the token table a file holds.

- [#135](https://github.com/atom63/atom63-design-system/pull/135) [`bf1592f`](https://github.com/atom63/atom63-design-system/commit/bf1592f024f0cd23bef2de0b4fdbbb893ac95ba3) Thanks [@atom63](https://github.com/atom63)! - Compute `oklch()` colors in Node, absolute and relative (`oklch(from var(--primary) … )`), so `atom63-figma sync` writes the site template's whole token set, the foreground colors included. The Figma plugin computes them with the same code, so the plugin and the CLI write the same values.

- [#141](https://github.com/atom63/atom63-design-system/pull/141) [`45f473a`](https://github.com/atom63/atom63-design-system/commit/45f473a02423faffddc85cdf458080baa84eb6a3) Thanks [@atom63](https://github.com/atom63)! - The last Button component script draws a spec card around the component set (summary, usage, per-variant, size and state guidance, related components, docs path and a labelled variant grid) bound to atom63 variables, and sets the set's description. Component and token scripts now carry separate runtimes, so token scripts are much smaller.

- [#126](https://github.com/atom63/atom63-design-system/pull/126) [`e06b9c1`](https://github.com/atom63/atom63-design-system/commit/e06b9c1b2ac491f9cd45fd8b347c9d66af762c2d) Thanks [@atom63](https://github.com/atom63)! - Sync writes text styles bound to size, line-height and font variables, and shadow effect styles, derived from the token set. `atom63-figma sync` reports the styles in its summary; `--no-styles` leaves them out.
