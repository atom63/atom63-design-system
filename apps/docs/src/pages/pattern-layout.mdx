# Page layout

`Page`, `Container`, and `Section` separate three decisions that otherwise drift together: the document landmark, the content frame, and the rhythm between page regions. They are composable defaults, not a required wrapper stack for every product shell.

## Responsibilities

| Primitive | Actual contract | Use when |
|-----------|-----------------|----------|
| `Page` | Renders `<main>` (or the element passed to `render`), fills the available height, adds `pt-8` and `pb-20` plus the bottom safe-area inset, and takes the wider side safe-area inset inline, unless `noPadding` is set | The route does not already have a main landmark, or it does and `Page` renders a `div` |
| `Container` | Centers a named max-width, adds a `gap` between direct children (`gap-8` by default), and applies `p-6`, `px-6`, or no padding | Content needs a shared measure or inline inset |
| `Section` | Renders `<section>`, applies a spacing preset, and optionally spaces direct children with a flex gap | A real page region needs repeatable vertical rhythm |

`Container` padding is not responsive: `padding="all"` is `p-6`, while `padding="x"` is `px-6`. `Section` owns breakpoint-dependent vertical padding. `tight` stays `py-8`; `default` stays `py-16`; `loose` changes from `py-16` to `py-20` at 768px. `generous` progresses from `py-20` to `py-28` at 640px and `py-32` at 768px; `spacious` progresses from `py-24` to `py-32` and `py-40`. Its default `removeTopSpacing` is `true`, so a section keeps its bottom padding but removes only the top padding at every breakpoint; set it to `false` for an opening region that needs the preset on both sides.

## Default composition

```tsx
import { Container, Page, Section, SectionHeader } from '@atom63/ui-react/layout'

<Page>
  <Container maxWidth="wide" padding="x">
    <Section removeTopSpacing={false} spacing="loose">
      <SectionHeader
        title="Projects"
        description="Selected product systems and interface work."
        variant="primary"
      />
    </Section>

    <Section>
      <ProjectGrid />
    </Section>
  </Container>
</Page>
```

The first section opts into top spacing. The second uses the default top removal because the container gap and preceding section already establish separation.

## Shell-owned layout

Do not add wrappers only to match the diagram. Current consumers deliberately stop at different layers:

- Design-system and Learn routes render `Page noPadding render={<div />}` because their app shells own the outer frame and the `main` landmark, then use `Container` and `Section` for reading layout.
- atom63.io route screens commonly let `SiteShellLayout` own the route surface and compose `Container > Section` inside it.
- Full-bleed desktops, split panes, and other application shells should use their own layout rather than force a document-page pattern.

```tsx
<Page noPadding render={<div />}>
  <Container maxWidth="widest" padding="none">
    <Section gap={false} spacing="tight">
      <ReaderLayout>{content}</ReaderLayout>
    </Section>
  </Container>
</Page>
```

## Choose the layout owner

| Decision | Owner |
|----------|-------|
| Main landmark, route inset and the bottom and inline safe-area insets | `Page` or the app shell, never both |
| Maximum width and outer padding | `Container` |
| Space around a page region | `Section` |
| Gap between cards or controls | The local grid, stack, or component |
| Card padding and control internals | The component |

Nested containers are valid when a region intentionally changes measure. Otherwise they usually indicate that page and component spacing have been mixed together.

## Accessibility boundary

`Page` renders `<main>` by default, so use it at most once in a document. When `Page` sits inside `SidebarInset`, the inset already renders `<main>` and owns the landmark: give `Page` `render={<div />}` so the document keeps exactly one `main`. `Section` always renders `<section>`; give the region an accessible heading rather than using it as a generic spacing wrapper, and name it with `aria-labelledby` pointing at the heading (`SectionHeader`'s `titleId`). The primitives provide structure, but they do not infer a heading outline.

## Primitives

### Page

The document landmark and the route's inset. Page owns the bottom and inline safe-area insets, which are 0 outside a notched or standalone screen; the top inset belongs to the header above it. Inside a shell that already renders `<main>`, pass `render={<div />}`; when the shell owns the inset too, add `noPadding`.

```tsx
<Page>
  <Container maxWidth="wide" padding="x">{content}</Container>
</Page>
```

<LayoutProps name="Page" />

It also takes the attributes of `<main>` and `render`, which replaces the element.

### Container

The content measure: a centred max-width with inline (or all-round) padding and a gap between its direct children. Its padding does not add the safe-area insets; `Page` or the app shell owns them. Set `gap` instead of overriding it with a class.

```tsx
<Container gap={6} maxWidth="wide" padding="none">
  <PageHeader title="Invoices" />
  <DataTableSection {...table} />
</Container>
```

### Section

A page region with a vertical spacing preset. Name it from its heading so it is a region landmark; other attributes and the ref reach the `<section>`.

```tsx
<Section aria-labelledby="pricing-title" removeTopSpacing={false} spacing="loose">
  <SectionHeader title="Pricing" titleId="pricing-title" variant="secondary" />
  <PricingTable />
</Section>
```

<LayoutProps name="Section" />

### SectionHeader

A heading with its description. `variant` sets the scale and `level` the heading element; the title and description take inline content such as a count badge or a link. `align` is logical: `start`, `center` or `end` follow the writing direction (`left` and `right` are deprecated aliases of `start` and `end`). The `label` variant keeps normal tracking in Chinese, Japanese and Korean.

```tsx
<SectionHeader
  description="Invoices past their due date."
  title={
    <>
      Overdue <Badge variant="error">3</Badge>
    </>
  }
  variant="secondary"
/>
```
