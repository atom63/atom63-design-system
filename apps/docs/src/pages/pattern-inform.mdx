# Inform

`@atom63/inform` is the pattern for telling a visitor something or guiding them to a control. It has one message model, one arbiter that decides what shows, and four surfaces: a banner, a dialog, a corner flyout and a spotlight.

```bash
pnpm add @atom63/inform
```

```css
@import '@atom63/styles';
@import '@atom63/ui-react/recipes.css';
@import '@atom63/inform/styles.css';
```

The package ships its own stylesheet and needs no Tailwind. Every color, space, radius, shadow and duration reads an `--a63-*` token, so the surfaces follow the theme, brand, mode and density.

| Entry point | Contents |
|-------------|----------|
| `@atom63/inform` | Message types, `defineInformRegistry`, `resolveInform`, `createInformStore` and the dismissal stores. No React. |
| `@atom63/inform/react` | `InformProvider`, `InformOutlet`, `useInform`, `useInformContext`. |
| `@atom63/inform/surfaces` | The four surfaces, `InformFlyoutStack`, and the icon, media and dismiss slots. Controlled, usable without the runtime. |

## The message model

Messages are data in a registry, not call sites. Each one names the surface it uses, a severity, a priority, its content and how it is dismissed:

```tsx
import { defineInformRegistry } from '@atom63/inform'

export const registry = defineInformRegistry([
  {
    id: 'maintenance',
    surface: 'banner',
    severity: 'warning',
    priority: 10,
    dismiss: 'session',
    endsAt: '2026-10-01T00:00:00Z',
    content: { title: 'Scheduled maintenance', body: 'Saving is paused from 02:00 to 03:00 UTC.' },
  },
  {
    id: 'command-menu',
    surface: 'spotlight',
    anchor: '#command-menu-trigger',
    severity: 'info',
    priority: 0,
    dismiss: 'persistent',
    when: ctx => ctx.pathname === '/',
    content: ctx => ({ title: 'Command menu', body: copy[ctx.locale].commandMenu }),
  },
])
```

| Field | Meaning |
|-------|---------|
| `id` | Stable identity and the dismissal key. `defineInformRegistry` rejects duplicates. |
| `surface` | `banner`, `dialog`, `corner-flyout` or `spotlight`. |
| `severity` | `info`, `success`, `warning` or `danger`. `info` is neutral; the others color the title and, on the banner, the border. |
| `priority` | Higher wins. Ties break by declaration order. |
| `dismiss` | `none` renders no dismiss control and never persists; `session` lasts until the tab closes; `persistent` survives it. |
| `version` | Bump it to show a message again to visitors who dismissed the previous revision. The dismissal key is `id:version`. |
| `startsAt`, `endsAt`, `when` | A time window and a predicate over the context (`pathname`, `locale`, `now`). |
| `anchor` | A CSS selector. Required on a spotlight and rejected on every other surface. |
| `content` | `title`, `body`, `actions`, and an optional `icon` and `media`, or a function of the context that returns them. Pass copy that is already localized. |

## The arbiter

`resolveInform` decides what each surface shows. It is a pure function of the registry, the context and the dismissals, so it is tested without a DOM:

1. **Filter.** A message drops out when it has been dismissed, is outside its time window, fails its `when` predicate, or is a spotlight whose anchor is not on the page.
2. **Rank** the rest per surface by priority, then declaration order.
3. **Exclude.** The dialog and the spotlight are blocking, and at most one of them shows; the dialog wins. While either is open the corner flyouts wait, and they come back when it closes. The banner is in the page flow and never takes part.
4. **Stack.** The banner, dialog and spotlight show one message each. The corner flyout shows up to three (`INFORM_FLYOUT_STACK_LIMIT`), and the rest queue until a visible card is dismissed.

The React layer wraps this in a store. Mount the provider once, and put outlets where the surfaces belong:

```tsx
import { InformOutlet, InformProvider } from '@atom63/inform/react'

<InformProvider context={{ pathname, locale, now: new Date() }} registry={registry}>
  <InformOutlet surfaces={['banner']} />
  <App />
  <InformOutlet flyoutOffset="5rem" surfaces={['dialog', 'corner-flyout', 'spotlight']} />
</InformProvider>
```

The provider reads the dismissal storage after mount, never during render, so a dismissed message does not flash for a frame. Pass `dismissals={createMemoryDismissalStore()}` in tests and stories.

## The surfaces

Every surface is controlled: it renders what it is given and reports a dismissal through `onDismiss`. The outlet is one consumer of them; you can render any of them directly.

### Banner

An in-flow notice that scrolls away with the page. It announces itself as a polite `status` and never takes focus. Use it for a standing notice that concerns the whole page: maintenance, a beta warning, a policy change.

<ExampleContainer align="left">
  <div className="grid w-full gap-3">
    <InformBanner body="Design system work in progress. You may experience issues." />
    <InformBanner
      body="Saving is paused from 02:00 to 03:00 UTC."
      dismissable
      severity="warning"
      title="Scheduled maintenance"
    />
    <InformBanner
      actions={[{ id: 'notes', label: 'Read the notes', onSelect: () => undefined, variant: 'primary' }]}
      body="Version 2 of the token pipeline is live."
      severity="success"
      title="Released"
    />
  </div>
</ExampleContainer>

The leading icon and the dismiss control each sit in a slot exactly one line tall, so they line up with the first line of text whether the message is one line or four. The dismiss control keeps a 24px touch target without growing its box. A banner ignores `media`.

### Dialog

A blocking notice built on the ui-react `Dialog`, so focus trapping, Escape, scroll locking and background inerting come from the primitive. Use it when the visitor has to read something before continuing. It can show full-width `media` above the text, at a fixed aspect ratio so a late image load shifts nothing.

</ExampleContainer>

### Corner flyout

A persistent card in a screen corner. Unlike a toast it has an identity in the registry, holds rich content and actions, and waits to be dismissed instead of expiring. It announces itself as a polite `status` and never takes focus. Use the `toaster` for transient feedback about something the visitor just did; use a flyout for something they are meant to act on.

<ExampleContainer align="left">
  <div style={{ width: 'min(22rem, 100%)' }}>
    <InformCornerFlyout
      actions={[{ id: 'read', label: 'Read it', onSelect: () => undefined, variant: 'primary' }]}
      body="A walkthrough of the windowing model is up."
      open
      title="New case study"
    />
  </div>
</ExampleContainer>

`InformFlyoutStack` places the cards in one corner (`placement`, `offset`). Collapsed, the front card shows in full and up to two peek out behind it; hovering or focusing the stack expands it. A card slides out before it reports its dismissal, and the next queued message takes its place. With `media`, the card shows a fixed square thumbnail in place of the severity icon, so its height stays predictable in the stack.

### Spotlight

A blocking guide step: a scrim with a cutout over one control and a bubble that explains it. The bubble flips above the control when there is no room below and stays inside the viewport. The spotlight traps focus, closes on Escape, restores focus on close and locks page scroll. Use it sparingly, for one control at a time; it is not a multi-step tour.

<ExampleContainer align="left">
  <SpotlightDemo />
</ExampleContainer>

A spotlight whose anchor is missing or has no size is skipped, never drawn over nothing.

## Choosing a surface

| Situation | Surface |
|-----------|---------|
| Something about the whole page, safe to ignore for now | Banner |
| The visitor must read it before continuing | Dialog |
| Something to act on later, without interrupting | Corner flyout |
| Explaining one control where it sits | Spotlight |
| Feedback about an action the visitor just took | Not inform: use the `toaster` |

Severity must be carried by the words, not only the color or the icon: the icons are decorative and hidden from assistive technology.
