# Craft rubric

Checks catch a literal color or a missing name. They do not catch a screen whose gaps are all legal tokens but have no rhythm, or a dialog with three primary buttons. This rubric writes that part of taste down as seven criteria, so a person in design review and a model judging agent output score a result the same way.

Each criterion has a definition, a 1–3 scale described by what you can see in the result, the checks that already cover part of it, and a live example that scores 3 next to one that scores 1. Every example that scores 1 passes the repo's checks: it is built from tokens, contract values and components, used poorly.

## How to score

Score each criterion on its own, from 1 to 3, against the level descriptions. When a result sits between two levels, give the lower score. Score what the result shows, not what it could do with small changes.

- **Passing:** no criterion scores 1. A result with a 1 fails, whatever its total, because one broken criterion, such as a keyboard path that does not work, is not offset by good spacing.
- **Total:** the sum of the seven scores, from 7 to 21. Use it to compare results, such as the same brief built with and without the design system. It is not a pass mark.
- **Evidence:** for each criterion, write one or two sentences that name what in the result earned the score: an element, a class, a prop or a state. "Rows use `py-3` and groups `gap-6`" is evidence; "feels balanced" is not.

A model judge outputs the scores as a JSON array with one entry per criterion:

```ts
type CraftScore = {
  criterion: string // a criterion id, such as 'spacing-rhythm'
  score: 1 | 2 | 3
  evidence: string
}
type CraftScores = CraftScore[]
```

<Callout type="info">

This page renders from that module, and so will the E4 vibe runner's judge prompt; `summarizeCraftScores()` there validates a judge's output and applies the passing rule. Change the rubric there, not on this page.
