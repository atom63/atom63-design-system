# Widgets foundation plan

Status: decided, 2026-09-25 (W1–W5 take their recommended options). This is the last D-phase item:
moving `packages/widgets/src/foundation` from atom63-vite into the design system.

## Goal

The design system already owns the widget contract: `--a63-widget-*` tokens in
`packages/styles/src/contracts/widget.css` (material, rim, radius, shadow, media shadow). The React
side of that contract lives in atom63-vite: widget units and scale, the widget card and surface,
and the loading, error and empty states. Move the generic part into the design system, so any app
can build widgets that follow the contract, and leave the portfolio widgets in atom63-vite.

## What exists (atom63-vite `origin/main`)

`packages/widgets/src/foundation` has about 4,000 lines and 134 Tailwind `className`s:

| Folder | Lines | `className` | Contents |
| --- | --- | --- | --- |
| `layout` | 1,043 | 4 | Widget units and spans, presentation scale, type floors, insets, `WidgetGrid`, `WidgetViewport` |
| `primitives` | 730 | 33 | `WidgetCard`, `WidgetSurface`, surface classes, `WidgetAvatar` |
| `state` | 329 | 20 | `WidgetStateFeedback` (loading, empty, error) |
| `runtime` | 430 | 22 | Hosted shell, loading shell, error fallback, content and title transitions |
| `host` | 308 | 22 | OS63 desktop and catalog chrome: drag handles, options button, catalog grid |
| `collection` | 562 | 28 | Stack view (Swiper card effect), poster fan, collection controls |
| root files | 423 | — | `WidgetImage`, `WidgetLink`, destination helpers, types |

Dependencies:
- `@atom63/icons` (the Iconify icon map that stays in atom63-vite) is used in 8 files.
- `swiper` is used in `collection/stack-view.tsx`.
- `motion` and `@atom63/ui-react` are used throughout.

Consumers: the 20 portfolio widgets in the same package, atom63.io and os63. There are about 50
imports of `@atom63/widgets`.

## Decisions

### W1. Scope

- **Options:**
  - **A. The generic core only:** `layout`, `primitives`, `state`, `runtime`, `WidgetImage`,
    `WidgetLink` and the types, about 2,900 lines. `host` (OS63 desktop drag and catalog chrome) and
    `collection` (Swiper stack and poster fan, which are presentation styles of the portfolio) stay
    in atom63-vite.
  - **B. The whole foundation folder.**
- **Trade-offs:** A moves only what every widget app needs, and keeps the OS63 host behavior and the
  Swiper dependency out of the design system. B also moves code that only OS63 can use, and adds
  Swiper to the design system's dependencies.
- **Recommendation: A.**

### W2. Icons

- **Background:** 8 files use `Icons` from the atom63-vite icon map. The design system keeps
  lucide as its default icon set (decided for icons in the D phase).
- **Options:**
  - **A. Lucide icons,** as the rest of `@atom63/ui-react` uses.
  - **B. An icon slot** on each component, so the host passes its own icons.
- **Trade-offs:** A is simple and consistent with the design system, but the widget chrome in
  atom63-vite changes from Material Symbols to lucide glyphs. B keeps the portfolio's icons, at the
  cost of an icon prop on every state and fallback component.
- **Recommendation: A.** The chrome icons are small (retry, error, empty, external link), and lucide
  matches the rest of the system. A general icon layer is a separate, later decision.

### W3. Styling

- **Proposal:** replace the Tailwind classes with a shipped stylesheet
  (`@atom63/widgets/styles.css`, `.a63-Widget*` classes) that uses the existing
  `--a63-widget-*` contract tokens and other `--a63-*` tokens, logical properties and
  `:focus-visible`. This is how `@atom63/inform` was moved. Exported class-name constants
  (such as the surface classes) keep their names, and their values become the stylesheet's classes.
  Add stories with a dark variant and visual baselines, axe tests and craft lint coverage.
- **Recommendation:** adopt it.

### W4. Package

- **Proposal:** `@atom63/widgets`, with subpaths that match the folders:
  - `.`: layout and types;
  - `./primitives`;
  - `./state`;
  - `./runtime`;
  - `./styles.css`.

  It is publishable, and it needs a first manual publish like inform and agent.
- **Consequence:** atom63-vite's own package is also called `@atom63/widgets`, so when it switches,
  it must rename its package (for example to `@atom63/portfolio-widgets`) and import the foundation
  from npm.
- **Recommendation:** adopt it.

### W5. iOS

- **Background:** the roadmap says widgets foundation needs a SwiftUI version too. The iOS side has
  the widget tokens, but no widget views.
- **Options:**
  - **A. Web first.** Add SwiftUI (`AtomWidgetCard`, the units and the state views) as a follow-up,
    with a cross-renderer contract generated by `pnpm ds:new --ios`-style wiring.
  - **B. Web and iOS in the same step.**
- **Trade-offs:** A lands the web move and lets the API settle before a second renderer copies it.
  B keeps the platforms in step, but doubles the size of one change that already touches about
  2,900 lines.
- **Recommendation: A.**

## Steps

1. **`@atom63/widgets` with `layout`, `primitives`, `state` and `runtime`,** in one pull request
   to avoid stacking. Stylesheet, stories, tests, docs page.
   *Verify:* craft lint clean, stories pass axe in both modes, and docs build without a prebuilt
   dist.
2. **atom63-vite switch** (after the first publish). Rename the local package, import the
   foundation from npm, and check atom63.io and os63 visually.
3. **SwiftUI widgets** (W5-A), in a separate plan.
