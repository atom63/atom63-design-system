# Contributing to Atom63 Design System

Thanks for helping improve Atom63. This guide covers how to report problems, set up the
repository, and get a change merged. Atom63 is a public beta; the
[support and governance policy](./docs/design-system/support-governance.md) describes what beta
support covers and who approves releases and support changes.

## Reporting problems

- **Bugs, accessibility problems, documentation fixes, and component proposals:** open a
  [GitHub issue](https://github.com/atom63/atom63-design-system/issues/new/choose) and pick the
  matching form. Include the smallest reproduction you can, the Atom63 package and version, and
  your runtime and browser versions.
- **Security vulnerabilities:** do not open a public issue. Follow [SECURITY.md](./SECURITY.md).

## Repository layout

| Path                     | Contents                                                              |
| ------------------------ | --------------------------------------------------------------------- |
| `packages/styles`        | `@atom63/styles`: CSS tokens, themes, contracts, and generated output |
| `packages/ui-foundation` | `@atom63/ui-foundation`: platform-neutral TypeScript contracts        |
| `packages/ui-react`      | `@atom63/ui-react`: React components                                  |
| `packages/ui-ios`        | `Atom63UI`: SwiftUI components, shipped through the root `Package.swift` |
| `apps/docs`              | The documentation site at [system.atom63.io](https://system.atom63.io) |
| `apps/figma-plugin`      | The Figma plugin that syncs tokens into Figma variables               |
| `examples/`              | Consumer examples for Vite, a product shell, and iOS                  |
| `scripts/design-system`  | Audits and guardrails run in CI                                       |

## Setup

You need Node.js 22 and the pnpm version pinned in `package.json` (enable it with Corepack).
Swift work also needs a current Xcode.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm --filter @atom63/ui-foundation build
pnpm --filter @atom63/ui-react build
```

Common development commands:

```bash
pnpm dev:docs                                  # documentation site
pnpm --filter @atom63/ui-react dev             # rebuild ui-react on change
pnpm --filter atom63-vite-basic-example dev    # run the Vite example against local packages
pnpm --filter @atom63/ui-react test            # component tests
swift test                                     # SwiftUI package tests
```

## Tokens and generated files

CSS in `packages/styles/src` is the source of truth for tokens. Several files are generated from
it and checked byte for byte in CI; regenerate them instead of editing them by hand:

```bash
pnpm --filter @atom63/styles generate:tokens      # token manifest, Figma sync model, z-layers
pnpm --filter @atom63/ui-react generate:utilities # precompiled utilities.css
```

Audit files in `docs/design-system/audits/` are regenerated by the matching `check:*` script with
`--write`, for example `pnpm check:ui-react-exports --write`.

## Before opening a pull request

Run the checks that cover your change. CI runs all of them:

```bash
pnpm format:check
pnpm --filter @atom63/ui-react lint
pnpm --filter @atom63/ui-react typecheck
pnpm --filter @atom63/ui-react test
pnpm --filter @atom63/styles check:tokens
pnpm check:ui-react-exports
pnpm check:package-surface
pnpm check:ds-pack-smoke
```

## Changesets

A change that affects a published package (`@atom63/styles`, `@atom63/ui-foundation`, or
`@atom63/ui-react`) needs a changeset:

```bash
pnpm changeset
```

Pick the affected packages and the bump type, then describe the change for consumers: what
changed and what they need to do. The repository is in beta prerelease mode, so versions are
published to the npm `beta` tag. Releases are automated: merging to `main` opens a "Version
Packages" pull request, and merging that pull request publishes. Contributors do not publish.

## Pull requests

- Keep each pull request focused on one change, and describe how you verified it.
- Update documentation and tests alongside behavior changes.
- A pull request can propose a new component or API, but it does not by itself change a support
  tier or authorize a release; see the
  [governance policy](./docs/design-system/support-governance.md).
